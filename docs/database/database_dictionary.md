# Music App Data Dictionary

This dictionary covers every column in the nine project application tables, using the live SQLite names and types. `INTEGER` primary keys are SQLite's representation for Django `BigAutoField`. All timestamps are generated by Django; SQLite has no timestamp default here. Examples are synthetic and illustrative, not values copied from actual user records. `—` means no separate key/constraint beyond NOT NULL where shown.

## `accounts_userprofile` — profile details linked to Django `auth_user`

| Column | Type | NULL | Constraint/default | Purpose and synthetic example |
|---|---|---|---|---|

| `display_name` | varchar(100) | No | Django blank default `''`; no SQL default | Name shown in the app; `Sample Listener` |
| `bio` | TEXT | No | Django blank default `''`; no SQL default | Optional profile description; `Enjoys jazz.` |
| `profile_image` | varchar(500) | No | Django blank default `''`; no SQL default | Optional avatar URL; `https://example.invalid/avatar.png` |
| `role` | varchar(10) | No | Django default `MEMBER`; choices are not SQLite CHECK | Application role; `MEMBER` |
| `created_at` | datetime | No | Django auto timestamp; no SQL default | Profile creation time; `2026-01-01 12:00:00` |
| `updated_at` | datetime | No | Django auto timestamp; no SQL default | Last profile update time; `2026-01-01 12:00:00` |
| `user_id` | integer | No | UNIQUE FK → `auth_user.id`, cascade | Owning account; `1` |

## `catalog_songartist` — song/artist junction

| Column | Type | NULL | Constraint/default | Purpose and synthetic example |
|---|---|---|---|---|
| `id` | INTEGER | No | PK, auto | Association row key; `1` |
| `role` | varchar(50) | No | Django default `Primary`; no SQL default | Performer role; `Featured` |
| `artist_id` | bigint | No | FK → `catalog_artist.id`, cascade; indexed | Linked artist; `1` |
| `song_id` | bigint | No | FK → `catalog_song.id`, cascade; indexed | Linked song; `1` |

The pair `(song_id, artist_id)` is UNIQUE; each artist-song association can occur once.

## `playlists_playlistsong` — ordered playlist/song junction

| Column | Type | NULL | Constraint/default | Purpose and synthetic example |
|---|---|---|---|---|
| `id` | INTEGER | No | PK, auto | Junction row key; `1` |
| `position` | integer unsigned | No | SQLite checks `>= 0` and `>= 1`; Django default `1`, no SQL default | Track's order in playlist; `1` |
| `added_at` | datetime | No | Django auto timestamp; no SQL default | When track was added; timestamp |

## Constraint note

SQLite `NOT NULL`, keys, unique indexes/constraints, and CHECK constraints are database-enforced. Django field lengths, URL validation, blank/form behavior, role choices, and Python defaults are application-layer rules in this schema. See [`relational_schema.md`](relational_schema.md) and [`ACTUAL_SCHEMA_AUDIT.md`](ACTUAL_SCHEMA_AUDIT.md).
